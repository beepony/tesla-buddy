# Tesla Companion — 产品需求说明书（PRD）

- 版本：0.1（规划稿）
- 日期：2026-07-26
- 目标平台：iPhone（iOS App）+ 家庭 Mac mini（本地服务）
- 数据主源：已部署的 TeslaMate PostgreSQL

## 1. 愿景与问题

把 TeslaMate 中分散、偏工程化的车辆数据，转化成一款打开即可理解、能帮助决策的私人用车助手：我现在的车况如何、这趟开得怎样、最近花了多少、下一次出行要注意什么。

产品不取代 Tesla 官方 App：首版不提供解锁、启动、空调等车辆控制，也不保存 Tesla 登录令牌。它专注于观测、分析与提醒，降低安全与合规风险。

## 2. 用户与使用场景

**主用户**：拥有一辆或多辆 Tesla、已在家中 Mac mini 运行 TeslaMate 的个人车主；重视数据隐私，也希望在手机上快速查看。

| 场景 | 用户问题 | 成功体验 |
| --- | --- | --- |
| 出门前 | 续航够不够、车在哪里、是否在充电？ | 主屏 3 秒内显示电量、预估续航、状态与最后同步时间。 |
| 行程后 | 此次行程耗电/效率怎样、路况是否影响？ | 自动生成行程卡片、地图、速度/能耗曲线与同类对比。 |
| 周/月复盘 | 里程、充电费用与效率有什么趋势？ | 一屏读懂周期指标，能切换车辆、时间范围、家庭/个人标签。 |
| 长途前 | 现有电量能否覆盖计划距离、充电是否异常？ | 提供保守续航提示和明确的、可关闭的提醒。 |
| 车辆长期维护 | 电池健康与轮胎/能耗有无趋势异常？ | 以趋势和置信度呈现，不作未经证实的机械故障诊断。 |

## 3. 产品范围

### 3.1 MVP（第一可用版本）

1. **安全连接**：iOS 通过局域网 HTTPS 访问 Mac mini 上的本地 API；配对后保存设备凭据；Mac mini 不向公网暴露数据库端口。
2. **车辆总览**：车辆名称、当前状态、位置（可隐藏精确位置）、电池百分比、额定/预估续航、里程、最后数据时间、充电状态。
3. **行程中心**：按日期浏览驾驶记录；显示起止时间/地点、距离、时长、平均能耗、海拔变化、轨迹与关键事件。
4. **充电中心**：充电记录、地点、起止 SOC、充入电量、时长、费用（有数据或用户录入时）、AC/DC 类型；支持按月汇总。
5. **报告**：本周、本月、今年三种周期：里程、驾驶时长、能耗、效率、充电量、费用、每百公里成本及趋势比较。
6. **提醒**：电量低于阈值、充电完成/中断、车辆长时间未同步；通知必须由用户按类别启用。
7. **设置与隐私**：车辆选择、单位（km/mi、kWh/100km、货币）、位置模糊化、数据刷新频率、导出 CSV/JSON。

### 3.2 第二阶段

- MQTT 订阅以缩短状态刷新延迟；断线回退到数据库轮询。
- 自定义报表构建器、标签（通勤/旅行/商务）、家庭共享与多设备。
- Home Screen 小组件、Live Activity、Siri Shortcuts。
- 基于个人历史的能耗/续航预测、充电价格规则与地理围栏。
- 可选远程访问：经 Tailscale/WireGuard 等私有网络，不开放裸露公网 API。

### 3.3 明确不做（MVP）

- 车辆控制、Tesla 账户授权、代替官方 App 的安全功能。
- 公共云账户、多租户服务、广告或第三方数据售卖。
- 医疗/安全级别承诺，或将数据推断表述为官方车辆诊断。

## 4. 功能需求与验收标准

### 4.1 信息架构

底部导航：**概览 / 行程 / 充电 / 报告 / 设置**。首屏使用信息优先级：当前是否可用 → 续航与充电 → 最新变化 → 本期摘要。

### 4.2 概览

- 支持多车切换；默认最近活跃车辆。
- 状态应包含：在线、行驶、驻车、充电、休眠、离线/数据过期。
- 显示“数据更新于 X 分钟前”，超过可配置阈值必须显著标为过期。
- 用户开启“精确位置”前，只展示区域级或不展示位置。
- **验收**：在同一局域网中，已缓存页面首屏打开 < 1 秒；手动刷新 P95 < 3 秒（Mac mini 空闲、数据库正常）。

### 4.3 行程

- 列表按开始时间倒序，支持车辆、日期区间、最小距离过滤。
- 详情含：路线地图、起终点（遵循位置隐私）、里程、时间、平均/总能耗、平均速度、海拔、SOC 变化。
- 支持将单次行程标记为“通勤/旅行/其他”，标签只存在本产品的应用数据库中。
- **验收**：选择 30 天时列表分页稳定；任意一条可回到列表时保留滚动和筛选条件。

### 4.4 充电与费用

- 充电记录按时间展示，可查看站点、SOC 区间、充电量、功率（若源数据存在）、时长与费用。
- 用户可补录/更正费用、币种、充电类型和备注；原始 TeslaMate 数据不可被修改。
- 报告优先使用已记录成本；没有成本时明确显示“费用未知”，不虚构电价。
- **验收**：月度费用等于纳入该月份且有成本记录的充电会话之和，可追溯到每笔记录。

### 4.5 报告与洞察

- 时间粒度：周、月、年、自定义区间；与上一等长区间比较。
- 指标：驾驶距离、驾驶时长、耗电、平均能耗、充电量、充电费用、每百公里成本、充电次数、最长单程。
- 图表：趋势线、按时段柱状图、充电类型占比、地点 Top 列表；无数据时提供说明而非空白图。
- 洞察为确定性规则生成，例如“本月每百公里能耗较上月高 12%，主要变化发生在最近两周”。每条洞察可点开查看计算口径。

### 4.6 通知

- 服务器根据最新快照与去重规则生成事件；iOS 只负责本机展示/本地通知。
- 低电量：SOC 低于用户阈值且车辆未充电；同一状态 12 小时最多提醒一次（可配置）。
- 数据过期：超过阈值无新状态时提示一次，不把休眠误判为故障。
- 软件更新：由 App 比较概览中的更新状态，目标版本高于已安装版本时本地提醒一次；同一目标版本不重复提醒。
- MVP 不使用 APNs 远程推送；App 前台刷新与 iOS 后台任务仅做尽力而为。可靠的跨网络推送归入第二阶段。

## 5. 数据、口径与隐私

### 5.1 数据来源与权威性

TeslaMate PostgreSQL 是车辆原始观测、行程、充电会话及其关联数据的事实来源；其模型/字段可能随 TeslaMate 版本演进，服务端必须通过适配层而非让 iOS 直连表结构。TeslaMate 官方说明其数据存放在 PostgreSQL，并支持向本地 MQTT Broker 发布车辆数据。[TeslaMate 官方仓库](https://github.com/teslamate-org/teslamate)

本项目另建独立的 `tesla_companion` schema（或独立数据库）保存：用户偏好、费用修订、标签、聚合缓存、设备配对、通知去重状态。永不向 TeslaMate 表写入数据。

### 5.2 数据最小化

- API 默认仅返回当前屏幕所需字段；位置轨迹按详情页按需取回。
- 服务器、数据库备份和 iOS 均须加密；日志不记录 token、精确坐标或完整 VIN。
- 删除设备会立刻撤销其访问令牌；清除本地 App 数据会移除 Keychain 中的凭据。
- 导出必须由用户明确触发，并可选是否包含位置。

### 5.3 关键计算口径

- 平均能耗 = 使用能量 ÷ 行驶距离；展示单位可切换，分母为零时显示不可用。
- 每百公里成本 = 充电成本 ÷ 对应驾驶距离 × 100；成本和距离的统计区间必须相同。
- “预估续航”以 TeslaMate 已记录值优先；自定义预测必须标注为估算及样本区间。
- 所有时间按车主选定时区聚合，原始时间以 UTC 存储/传输。

## 6. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 安全 | 无明文密钥；短期访问令牌；TLS；限速；所有查询参数化；最小权限数据库角色。 |
| 隐私 | 默认仅局域网；默认隐藏精确位置；零第三方分析 SDK。 |
| 可用性 | Mac mini/数据库不可用时 App 告知最近缓存时间，不显示误导性的“实时”。 |
| 性能 | 常用总览 API P95 < 500ms；报告接口 P95 < 2s；重计算在后台完成。 |
| 兼容性 | 首版目标 iOS 17+，SwiftUI；服务端在 Apple Silicon macOS + Docker 或原生运行。 |
| 可维护性 | 数据访问契约测试覆盖所支持的 TeslaMate 版本；数据库升级前后可做只读健康检查。 |

## 7. 技术架构（建议）

```text
Tesla 车辆 → TeslaMate → PostgreSQL（只读账户） ─┐
                    └→ MQTT（可选，第二阶段）    ├→ 本地 API（Mac mini） → iOS App / Widget
应用偏好、修订、聚合缓存 ─────────────────────────┘
```

- **iOS**：Swift 6、SwiftUI、Charts、MapKit、SwiftData（缓存）、Keychain、URLSession；模块化但单 App target 起步。
- **本地 API**：TypeScript + Fastify（建议）或同等轻量框架；OpenAPI-first；后台任务计算聚合和事件。
- **数据库**：既有 TeslaMate PostgreSQL 以只读角色接入；Companion 私有 schema 使用独立读写角色。连接池必须分开。
- **部署**：Docker Compose 管理 API 与迁移；仅绑定局域网 IP；Caddy/Traefik 提供本地 TLS（实际选型在环境核查后定）。
- **认证**：首次在可信局域网扫描二维码/一次性配对码，服务端登记设备公钥或随机设备密钥；令牌在 iOS Keychain 保存与轮换。

## 8. API 草案（MVP）

所有接口前缀 `/v1`，JSON 使用 ISO 8601 UTC 时间，数值使用原始公制单位；客户端负责本地化显示。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/pairing/start`, `/pairing/complete` | 设备配对（仅首次） |
| GET | `/vehicles` | 可访问车辆与当前摘要 |
| GET | `/vehicles/{id}/overview` | 单车总览与数据时效 |
| GET | `/vehicles/{id}/drives` | 行程分页/筛选 |
| GET | `/drives/{id}` | 行程详情及按需轨迹 |
| GET | `/vehicles/{id}/charges` | 充电分页/筛选 |
| PATCH | `/charges/{id}/annotation` | 保存费用/备注等应用侧标注 |
| GET | `/reports/summary` | 给定车辆与区间的指标、趋势、洞察 |
| GET/PATCH | `/settings` | 单位、隐私、通知偏好 |
| GET | `/health` | 不含敏感信息的存活与依赖状态 |

## 9. 实施里程碑

| 阶段 | 可交付物 | 完成标准 |
| --- | --- | --- |
| 0：发现与契约 | 环境盘点、真实表结构快照（脱敏）、API 契约、设计基线 | 能用只读账号完成 3 个代表性查询。 |
| 1：项目骨架 | Compose、API、迁移、OpenAPI、iOS SwiftUI 壳、CI | 空项目可一键本地启动且 iOS 可显示 mock 总览。 |
| 2：数据 MVP | 总览/行程/充电 API 和 iOS 页面、缓存 | 在真实历史数据上可完成核心浏览。 |
| 3：报告 | 聚合、费用标注、图表、导出 | 周月报告与数据库抽查结果一致。 |
| 4：配对与提醒 | TLS、配对、令牌、阈值提醒、审计日志 | 未配对设备无法读取任何车辆数据。 |
| 5：打磨与发布 | 测试、备份/恢复演练、性能与隐私审查、TestFlight | 连续一周稳定运行，验收清单通过。 |

## 10. 风险与决策

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| TeslaMate schema 版本差异 | 查询失效/数字不一致 | 建立版本探测、适配器与契约测试；不把表名暴露给客户端。 |
| Mac mini 休眠或网络变化 | 数据不同步/无法访问 | 明示数据时效；配置防休眠；局域网优先；远程访问后置。 |
| 位置与驾驶记录敏感 | 隐私泄露 | 默认最小化、只读、TLS、设备配对、无云端。 |
| iOS 后台限制 | 无法保证实时通知 | MVP 采用应用刷新/本地提醒；第二阶段引入受控远程网络与推送。 |
| 费用原始数据不完整 | 报表误导 | 明确未知状态，提供应用侧可追溯补录。 |

## 11. 待确认项（进入编码前）

1. TeslaMate 的部署方式、版本、PostgreSQL 容器/主机位置及是否已有 MQTT。
2. 首版是否必须支持外网访问；若需要，是否接受 Tailscale 这类私有网络方案。
3. 目标车型、车辆数量、主要国家/币种与是否需要中文/英文双语。
4. 费用数据的来源：TeslaMate 已有、手动补录，还是要接入电价规则。
5. iOS 开发签名、真机与 TestFlight 的 Apple Developer 账号是否已具备。

## 12. 首轮验收清单

- App 可经一次配对连接到局域网内服务，且重装 App 后必须重新配对。
- 不向 TeslaMate 表执行 INSERT/UPDATE/DELETE；以数据库权限验证。
- 总览、最近 30 天行程、最近 30 天充电在真实数据上均可用。
- 报表的距离、费用、能耗能抽样追溯到源记录，口径在界面可见。
- 手机离开家庭网络或服务端停止时，App 安全失败并展示最后缓存时间。
